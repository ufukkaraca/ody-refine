The Problem

73% of your docs are outdated.
You just don't know which 73%.

Knowledge breaks silently. A Slack thread overrides a doc nobody updates. A process changes but the runbook doesn't. A committed SLA expires without a renewal. Nobody notices until it causes a problem.

"I tried to do this manually last quarter. It took two days and I only covered 30% of the docs."

"We have three different answers to the same question depending on which page a new hire lands on."

— VP Engineering, YC-backed startup

— Chief of Staff, 25-person fintech

Five Detectors

Pure functions. No LLM required.

Each detector is a pure function you can read, test, and fork. They build a semantic claim graph and walk it — no embedding magic, no black boxes.

✗
Contradiction

Two sources make incompatible assertions about the same concept. Detects semantic disagreement even when different words are used — "max throughput" vs "rate limit cap" are the same claim.

Real finding
api-reference.md:44 → "GPU allocation: 256 per job"
infra-guide.md:18 → "GPU allocation: 64 per job"
CONFLICT — incompatible values
⚠
Staleness

Commitments and processes that haven't been updated. Finds "weekly sync" mentioned in a doc that has zero evidence of execution in 4 months, "Q3 migration" that's now Q4.

Real finding
PROCESS.md → "Weekly architecture review"
Last evidence: 4 months ago (Slack #eng)
STALE — process may be abandoned
⊘
Duplicate with Drift

The same knowledge documented in two or more places that have diverged over time. Detects when copies start saying different things — a silent source of confusion.

Real finding
onboarding/new-hire.md → "30-day check-in with manager"
hr/process.md → "60-day check-in with manager"
DRIFT — copies have diverged
ℹ
Undocumented Decision

Something decided in a conversation but never written down. Finds the Slack thread where engineering agreed to deprecate an endpoint that's still described as active in every doc.

Real finding
#eng Nov 12 → "we're deprecating v1 API end of year"
api-reference.md → v1 still documented as active
UNDOCUMENTED — decision not written down
⏰
Time Bomb

A deadline, SLA, or commitment approaching expiry with no renewal or resolution doc. The customer contract that expires in 14 days. The SSL cert with no rotation runbook.

Real finding
contracts/acme.md → SLA renewal due in 14 days
No renewal doc or ticket found in any source
EXPIRY — commitment unaddressed
How it works

Three commands.
Instant clarity.

1
Point at your docs

Any folder of markdown, a Notion export, a Confluence export, or exported Slack JSON. Mix and match.

npx ody-refine ./docs/
2
Refine scans & detects

Builds a semantic claim graph from your sources. Five detectors walk the graph and surface issues ranked by severity.

~2 min for 1,000 files
3
Read the report

An HTML report with every finding, source citations, confidence score, and suggested resolution. Export to JSON for CI integration.

./ody-report.html
Why Refine

The tool your team's been running manually.

  • ✓
    Zero-trust entry point

    Runs entirely on your machine. Every line of code is auditable. No account, no API key, no data ever sent anywhere.

  • ✓
    Graph-walk, not keyword match

    Builds a semantic claim graph and walks it. "Max throughput" and "rate limiting cap" resolve to the same claim — different words, same conflict.

  • ✓
    Works with what you have

    Markdown folders, Notion exports, Confluence exports, Slack JSON — no integration setup, no OAuth flow. Just point and run.
